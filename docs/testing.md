# Validation methodology

Use `make validate` or `python3 scripts/manage.py validate`. The command writes
`artifacts/validation.log` as each real subprocess executes, then publishes
`artifacts/validation.json`. It records command lines, exit status, durations,
test counts, category counts, coverage, exact scenario results, Sigma results,
the benchmark, and a content fingerprint. A failed/interrupted phase exits
nonzero and records FAILED. Previous result files are retired at the start;
stale green receipts cannot stand in for current execution.

## What executes

| Phase | Evidence |
|---|---|
| Environment / dependency consistency | Node version check, `pip check`, locked installs |
| Backend static / types | Ruff check + format check, strict MyPy on `backend/app` |
| Frontend static / build | ESLint, Prettier check, TypeScript and Vite production build |
| Data reproducibility | Regenerate synthetic data in temporary storage and compare every generated file byte-for-byte |
| Backend tests | Full pytest run, JUnit XML, actual coverage JSON |
| Frontend tests | Vitest JSON report, API/state interaction and accessibility-oriented component tests |
| Parser contracts | Five saved contracts / 21 full expected normalized objects, not merely successful parsing |
| Positive / controlled negative | Every bundled detection, authored rule/severity/branch/evidence-count contracts |
| Storage / API / evidence | Ingest through normalization, persistence, rule evaluation, alert, evidence, raw record, statuses, search, dashboard |
| Replay | All major positive datasets, real 10x pacing, progress, repeated runs, duplicate input, disabled rules, cancellation/capacity/restart |
| Sigma | Two unchanged licensed rules; explicit filters, logsource constraints, import-to-alert provenance |
| Regressions | Every rule family; window expiry, grouping, duplicates/conflicts, late/tied timestamps, status/snapshot persistence |
| Security | Safe decoding, nonfinite/oversized values, duplicate keys, YAML tags/aliases, regex timeout/rollback, SQL parameters, XSS-text preservation, auth/origin/Host/file limits |
| Benchmark | Included 5,600 events, 39,200 rule evaluations and exact 700-alert contract, plus actual timings |
| Optional integrations | OAuth/query/pagination mocks, scoped Windows spool/API harness, checkpoint rollback, late events, retries, receiver receipts and three provider benign scenarios |

Backend categories overlap. The reported **total unique tests** is backend
test cases plus frontend test cases, not the sum of overlapping categories or
repeated subprocess scenarios. Detection validation and Sigma compatibility
also report their own real case counts. Empty or skipped required categories
are not accepted as a validated result.

.venv/bin/python -m pytest backend/tests/unit

.venv/bin/python -m pytest -m security
npm --prefix frontend test
.venv/bin/python scripts/validate_detections.py --dataset auth-brute-force
.venv/bin/python scripts/validate_detections.py --dataset auth-normal-failures --rule AUTH-001

.venv/bin/python -m pytest backend/tests/integrations

All fixture inputs are saved in `test-data/`; parser expected objects and exact
scenario contracts live in `test-data/expected-results/`. Assertions are not
generated by running the detector first. Unit tests also derive bounded input
mutations from these saved fixtures to exercise invalid types and boundaries.

## Bugs reproduced and prevented

The regression suite includes actual initially failing reproducers for JSON
exponent overflow (`1e400`), YAML nonfinite values, huge JSON integers, unquoted
Sigma date metadata, malformed Sigma status types, non-ASCII bearer headers,
reset/fixture ordering, advertised alert-search fields, and custom development
port origins. Fixes were followed by a complete suite rerun.
Runtime regex timeouts roll back the entire ingest, rather than silently
treating a timeout as a benign non-match.

The live browser workflow also checks ingestion through the UI, raw evidence,
status persistence, disabled-definition testing, replay progress, unsupported
Sigma rejection, all eight main pages at 1440px and 390px, mobile navigation,
single-line technique identifiers, keyboard skip navigation, and unexpected
HTTP/page errors. These 33 checks supplement, rather than inflate, unit-test
counts. Media is captured only after the full validation receipt is current.

The fresh-install npm advisory report also produced eight initially failing
lockfile regression checks. After upgrading React Router, Vite, Vitest and
Playwright, all eight pass and `npm audit --json` reports zero known advisories.
The offline guards cover the documented known version floors, not future
advisories. The live registry query is deliberately separate from offline
`make validate`; see [dependency maintenance](dependency-maintenance.md).

## Isolation and scope

Tests use temporary SQLite databases, not the live demo database.
Detection validation creates fresh in-memory engine state for **each** dataset.
Replays create fresh persisted run IDs. Dataset checksums reject edited inputs
unless explicitly regenerated. `scope=bundled` tests shipped definitions;
`scope=current` deliberately tests changed operational enablement and can fail
the same expectations. A disabled rule can be tested in explicit definition
mode without re-enabling it.

The baseline is controlled, predominantly synthetic telemetry. Passing included
scenarios does not establish enterprise false-positive rates, full ATT&CK
coverage, or efficacy against unseen attacks. The public sample is a parser
interoperability test, not a claimed detection benchmark.

## Benchmark interpretation

The generator persists 100 hourly copies of the 56-event mixed incident, with
unique IDs and shifted timestamps. Expected results are independently authored:
5,600 unique events, 700 alerts, 100 per rule, and 39,200 evaluations with seven
enabled rules. The benchmark asserts these counts on every measured iteration.

Reported throughput uses the median of actual engine durations; raw samples,
Python/platform, timestamp, fixture hash, and source fingerprint are saved.
Parsing, SQL storage, UI updates, and live append re-evaluation are **excluded**.
No production capacity or timing SLA is implied. See the committed actual
measurement in `docs/results/benchmark.json`.

## Deployment verification

Deployment regressions preserve the original private health response and
exercise public initialization, protected reset, state persistence, schema/data
ownership, synthetic-only catalogs, pinned Sigma sources, resource limits,
configured hosts/origins, and read-only frontend controls. The frontend also
tests API-base normalization, hosted configuration rejection, and delayed mode
discovery without fetching private developer evidence.

An actual Linux/amd64 image build found SQLAlchemy's platform-conditional
`greenlet` dependency missing from the macOS-generated hash lock. Two offline
metadata regressions failed before its explicit pin was added. No existing
package version was upgraded or hash enforcement bypassed. Another real
container run exposed an early connection reset from Docker's port proxy;
readiness now retries only transient connection errors with a bounded deadline,
never treating an exited server as ready.

```sh
make validate
.venv/bin/python scripts/verify_deployment.py \
  --label native-check-1 --backend-port 18865 --frontend-port 18875
.venv/bin/python scripts/verify_deployment.py \
  --label docker-check-1 --docker --backend-port 18866 --frontend-port 18876
```

Use fresh labels and unoccupied ports. The verifier checks the current validation
fingerprint before starting and rejects source changes during a rehearsal.
Public browser tests use production assets, no Vite proxy, real cross-origin
POSTs, and Chromium's complete headers on finished requests (the provisional
view omits Origin, while cancelled navigation reads may never finish). The
browser command has a bounded timeout. Tests do not inject an owner token. Desktop/mobile
screenshots are separate artifacts, never replacements for original media.

The public API validates 49 synthetic scenarios; `make validate` still exercises
all 50 local scenarios and all 14 benign cases. Public and private browser case
counts are separate from unique backend/frontend unit and integration tests.
See [deployment-readiness.md](deployment-readiness.md) for exact executed counts,
before/after findings, container scope and final-source clone evidence.

## Integration-phase verification

`make validate` also checks the integration fixture and notification-schema
generator byte-for-byte, runs the real local HTTP end-to-end validator, and
requires nonempty `connectors`, `notifications`, `migration` and `end_to_end`
categories. These markers overlap the other backend categories and must not be
added together as unique test totals. Three additional provider-benign cases
are tests, not hidden additions to the historical 50 detection scenarios.

For a separately started, isolated private backend on unused ports:

```sh
SENTINEL_UI_URL=http://127.0.0.1:18881 \
SENTINEL_API_URL=http://127.0.0.1:18881 \
node scripts/browser_verify.mjs --no-capture --preserve-database
SENTINEL_UI_URL=http://127.0.0.1:18881 \
SENTINEL_API_URL=http://127.0.0.1:18881 \
node scripts/browser_integrations.mjs
```

The preservation flag imports a new scoped incident instead of resetting the
database and requires `--no-capture`. It still creates test runs/status changes;
use an isolated database, never an unrelated live installation.
The integration browser workflow records current real API/UI behavior and
separate new screenshots, never overwriting original `screenshots/` or recordings.
Results and exact live-testing limitations are recorded in
[integrations-implementation-report.md](integrations-implementation-report.md).
